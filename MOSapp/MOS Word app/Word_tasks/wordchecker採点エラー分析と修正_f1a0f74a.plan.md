# WordChecker 採点エラー分析と修正計画

## 前提

- **解答済み=True**: 操作していない初期状態で正解になる（甘い判定）
- **フラグ=True**: 正しい操作をしているのに不正解になる（厳しすぎる判定）
- 採点は [UiTestAppBarWindow.xaml.cs](MOSapp/MOS Word app/Views/UiTestAppBarWindow.xaml.cs) で `CheckTask_1_{プロジェクト}_{タスク:D2}` をリフレクションで呼び出している
- VSTO必須問題は [VSTOCheckerHelper.cs](MOSapp/MOS Word app/Libraries/VSTOCheckerHelper.cs) に定義（1-1, 2-1, 4-2, 4-3, 6-1, 7-1, 7-4, 7-5, 8-1）

## 3. 修正の優先順位と進め方

1. **VSTO必須に統一するだけの変更（影響が分かりやすい）**
  - 1_4_03, 1_7_01, 1_7_04, 1_7_05 の「ログなし時は文書のみ」分岐を削除し、ログありかつ該当コマンド実行時のみ true を返すようにする。
2. **コードのみで直せる明確なバグ**
  - 1_4_07: ヘッダー・フッターを Trim / IsNullOrWhiteSpace で判定。  
  - 1_7_03: 「インテグラル」を含む場合のみ正解（`Length > 0` の OR を削除）。  
  - 1_6_04 / 1_6_06: 検索文字列の全角「２」と半角「2」の両方を試す。  
  - 1_2_03: TintAndShade の許容範囲を少し広げる。  
  - 1_3_01: 余白の tolerance を 2〜3pt に広げる。
3. **簡略化の解除（実装コスト大）**
  - 1_4_04, 1_4_05, 1_4_06, 1_6_05, 1_8_05, 1_8_06, 1_9_xx, 1_10_02, 1_10_03 など、`return true` や「常に通過」にしている箇所を、問題仕様に合わせた文書判定に順次変更する。
4. **VSTO アドイン側の確認**
  - 6-1（TableConvertTextToTable）、8-1（TocAutomatic2）など、正解操作をしているのに不正解になる場合は、該当操作でログが確実に出力されているかを VSTO の Ribbon イベントで確認する。

## 4. 判別まとめ

- **コード修正のみで対応できるもの**: P1T5, P2T3, P3T1, P3T5, P4T1, P4T7, P4T4, P4T5, P4T6, P5T2, P6T4, P6T5, P6T6, P7T2, P7T3, P8T3, P8T4, P8T7, P9T1, P9T5, P10T1, P10T2, P10T3, P10T5 など（上表の「コード」対応）。  
- **VSTOログ必須にすべきもの**: P4T3, P7T1, P7T4, P7T5（ログなし時は false に統一）。  
- **VSTOログの確認・出力追加が必要な可能性**: P6T1（TableConvertTextToTable）, P8T1（TocAutomatic2）。  
- **初期状態で正解になるのを防ぐには**: 上記の「VSTO必須に統一」と、常に true を返している簡略化の解除（1_4_04, 1_4_05, 1_6_05, 1_7_03, 1_8_05, 1_8_06 等）が必須。

以上の順で修正を進めると、解答済み=True とフラグ=True の両方を減らせます。
