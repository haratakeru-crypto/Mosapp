# 開発支援アジェンダ

## 概要

本ドキュメントは、MOS試験採点システムの開発において、現在直面している2つの主要な課題について、解決に向けたアジェンダをまとめたものです。

---

## 課題1: Word VSTOアドインの開発と精度向上

### 現状の問題

- **目的**: Wordアプリのチェッカーの精度を向上させるためのVSTOアドインを作成しているが、うまくいかない
- **参考資料**:
  - `Reference/md/# Word VSTOアドイン開発依頼（MOS試験採点用）.md`
  - `Reference/md/ID,問題概要,VSTO推奨理由,監視対象コマンド例.md`

### 開発要件

#### 監視対象コマンド

| ID | 操作内容 | 監視すべきコマンド (idMso) | 備考 |
|:---|:---|:---|:---|
| **1-1** | 編集記号の表示/非表示 | `ShowAll` | トグルボタン。On/Offに関わらずクリックを検知 |
| **2-1** | 文字列の切り取り・貼り付け | `Cut`, `Paste` | コピペ vs 切り取りの判定 |
| **4-2/4-3** | コメント操作 | `ReviewNewComment`, `ReviewDeleteComment` | 返信・解決ボタンの使用判定 |
| **6-1** | 文字列を表に変換 | `TableConvertTextToTable` | 機能使用の証明 |
| **7-1** | 互換モードの解除 | `UpgradeDocument` | バックステージ操作の検知 |
| **7-4/7-5** | 名前を付けて保存 | `FileSaveAs` | 保存プロセスの監視 |
| **8-1** | 目次の挿入 | `TableOfContentsGallery` / `TocAutomatic2` | ギャラリー選択の判定 |

#### 実装要件

1. **Ribbon XML (`Ribbon.xml`)**
   - 上記の `idMso` をターゲットにした `<commands>` タグ定義
   - 既存のUIを隠さず、裏側でイベントだけをフック

2. **コールバック処理 (`Ribbon.cs` / `ThisAddIn.cs`)**
   - `onAction` イベントハンドラを実装
   - 実行されたコマンドのIDを識別し、ログ出力メソッドに渡す
   - **重要**: ログ出力後、`cancelDefault = false` とし、Word本来の機能が正常に動作するようにする

3. **ログ出力仕様**
   - 出力先: `Path.GetTempPath()` 内の `mos_word_log.txt`
   - 出力形式: `[yyyy-MM-dd HH:mm:ss] [CommandID] Executed`
   - 排他制御: `lock` を使用してファイル書き込みの競合を防ぐ

#### プロジェクト構造

```
MOS Word app/
└── MOSWordVSTOAddIn/                 # VSTOアドイン専用プロジェクト
    ├── MOSWordVSTOAddIn.csproj       # プロジェクトファイル
    ├── Logger.cs                     # ログ出力クラス
    ├── Ribbon.cs                     # Ribbonコールバック
    ├── Ribbon.xml                    # Ribbon定義（埋め込みリソース）
    ├── ThisAddIn.cs                  # アドインエントリーポイント
    ├── ThisAddIn.Designer.cs         # 自動生成補助
    ├── Properties/
    │   └── AssemblyInfo.cs
    └── bin/Debug/                    # ビルド出力（.dll, .manifest, .vsto）
```

## 課題2: Excelアプリの外部提供におけるセキュリティ対策

### 現状の問題

- **目的**: Excelアプリを外部の講師に不具合（バグや不正解なのに正解判定されるような現象）を調査していただくために提供したい
- **懸念事項**: アプリの機密情報を守る必要がある
- **参考資料**: [リバースエンジニアリング（逆コンパイル）からアプリを守る方法](https://qiita.com/agtech_tomoito/items/9aacc638704168c06baf)

### セキュリティ要件

#### 保護すべき情報

- ソースコード（アルゴリズム、ビジネスロジック）
- 内部データ構造
- 認証情報やAPIキー（含まれている場合）
- その他の機密情報

#### 検討すべき対策

1. **難読化（Obfuscation）**
   - **目的**: コードのリバースエンジニアリングを困難にする
   - **ツール**: Dotfuscator（Visual Studioにバンドル）
   - **効果**:
     - 名前の変更: クラス名、メソッド名、変数名などを意味のない文字列に置き換え
     - 文字列の暗号化: コード中に埋め込まれた文字列リテラルを暗号化
     - 制御フローの難読化: 無意味な分岐や計算などのダミーコードを挿入
   - **注意点**:
     - Visual Studio Community版に付属する「Dotfuscator Community」は名前の変更のみ
     - 高度な難読化には「Dotfuscator Professional」のライセンスが必要

2. **パスワード保護**
   - Excelファイル自体にパスワードを設定
   - VBAマクロのパスワード保護（含まれている場合）
   - 実行ファイルのパスワード保護（.exeの場合）

3. **その他の対策**
   - 機密情報の除去（ハードコードされた認証情報など）
   - デバッグ情報の削除
   - 不要なコメントの削除
   - 最小限の機能のみを含むバージョンの提供

### 必要な支援内容

- [ ] 現在のExcelアプリの構造と機密情報の特定
- [ ] 難読化ツールの選定と導入方法の検討

## 採点・ビルド確認（チェッカーDLL）

- **チェッカーDLLの配置**: メインアプリは `bin\Debug\Dlls\`（または `bin\Release\Dlls\`）から `WordChecker1_1.dll` ～ `WordChecker1_10.dll` を読み込む。
- **確認手順**:
  1. ソリューションをビルドする。
  2. `MOS Word app\bin\Debug\Dlls\`（または Release の場合は `bin\Release\Dlls\`）に `WordChecker1_1.dll` ～ `WordChecker1_10.dll` が存在することを確認する。
  3. 存在しない場合は、`Libraries\Group1` の各 WordChecker プロジェクトの `OutputPath` が `..\..\bin\$(Configuration)\Dlls\` になっているか確認し、再ビルドする。
- 採点実行時に例外が発生した場合は、Visual Studio の「出力」ウィンドウ（デバッグ時）に `[ExecuteScore] 採点エラー: ...` が出力される。
