# Excel 類題（練習バリエーション）作成 — 実装土台ガイド

演習タブ（Tab1）向けに、**類題**（教材と似た操作の別問題）を作り、**採点機能（Checker）を作り**、**今のアプリの画面のまま VS で採点を確かめる**ための手順書です。

**この文書の範囲**

- 類題の Excel・Checker・問題文を作る
- `config.json` の `library` を一時的に変えて、VS で採点確認する

**この文書に含まないもの**

- アプリバーの「類題ボタン」
- 類題モードの自動切替（`GetProjectFilePath` の改修、`practiceVariants` 設定など）

それらは別途、本番アプリ改修として扱います。

Cursor に作業を依頼するときは、あわせて次を渡してください。

- `tasks/Excel_類題実装_実行プロンプト.md`

### どれから始めるか

| 順番 | 目的 | 読む章 | 使うプロンプト |
|------|------|--------|----------------|
| **1（推奨）** | 成功体験：採点と問題文がタスク1だけ動くことを確認 | §5 | 実行プロンプト §1「先行体験」 |
| **2** | 1プロジェクト分を一通り作る | §7 | 実行プロンプト §2「本番」 |
| **3（将来）** | アプリに類題ボタン等を組み込む | 別ドキュメント | 本 MD の範囲外 |

§5 の先行体験が終わってから §7 に進むと、手順がぶれにくいです。

| 呼び方 | 意味 |

## 1. 類題を動かすために必要な3つ

類題は、次の3つが**セット**になっていないと正しく動きません。

| # | 何か | どこにあるか | いまの確認方法 |
|---|------|--------------|----------------|
| 1 | **Excel 問題ファイル** | `C:\MOSTest\Excel365\Tab1\Initial\project{N}.xlsx` | このフォルダのファイルをそのまま編集・使用 |
| 2 | **採点チェッカー** | `Libraries\Group1\ExcelChecker*.cs`（DLL） | `mos_xaml_app\Assets\config.json` の `library` を変更 |
| 3 | **問題文** | `References\JSON\MOS演習問題文一覧.json` | この JSON を類題用の文言に合わせて編集 |

### 1.1 Excel ファイルについて（重要）

アプリは、プロジェクトを開くとき **必ず** 次の場所を見ます。

```
C:\MOSTest\Excel365\Tab1\Initial\project{番号}.xlsx
```

`config.json` の `excelFile` を書き換えても、上の `Initial` にファイルがある限り **そちらが優先** されます。

**方針:** 別フォルダへのコピーや退避は行いません。  
類題用の Excel は、**いつも通り `Tab1\Initial\` に置いたファイルをそのまま使います。**

リセット機能を試す場合は、同様に **`Tab1\Templates\`** のファイルをそのまま使います。

### 1.2 採点チェッカーについて

採点ボタンを押すと、アプリは `config.json` に書いてある `library` の名前で Checker を呼び出します。

```json
"1": {
  "taskCount": 5,
  "library": "ExcelChecker1_2",
  ...
}
```

類題を試すときは、ここの `library` を **類題用 Checker 名**（§3 の表の「類題1 Checker」列）に変えます。

※ **プロジェクト番号と Checker 名の数字は一致しません**（1〜3、7〜9 は特に注意）。  
必ず §3 の対応表か、config の `"N"` の `library` を確認してください。

### 1.3 問題文について

演習タブ（GroupId=1）の問題文は、次の1ファイルから読み込まれます。

- `MOSapp/mos_xaml_app/References/JSON/MOS演習問題文一覧.json`

確認中は、この JSON を **類題用の文言に直接合わせて編集** します。  
類題ごとに原稿を残したい場合は、`_PracticeVariant1` 付きの別ファイルに書いておき、確認用にメイン JSON を更新しても構いません。

## 4. 進め方の全体像

類題づくりは、次の **2段階** で進めます。いきなり全タスクを作らなくて大丈夫です。

```
【段階A】先行体験（§5）          【段階B】本番作業（§7）
  タスク1だけ類題採点・問題文        プロジェクト1の全タスク
  採点と問題文が動く体験を先に  →    残りのタスク・Excel も含めて完成
  土台ボタン等は作らない             土台ボタン等は作らない
```

| 段階 | いつ使うか | ゴール |
|------|------------|--------|
| **A: 先行体験** | 初めて Cursor で類題採点を試すとき | タスク1で **類題の問題文が表示**され、**〇/✖ が返る** |
| **B: 本番作業** | 先行体験のあと、1プロジェクトを仕上げるとき | 全タスク・問題文・Excel が揃い採点確認できる |

**段階Aで作った `ExcelChecker*_PV1.cs` は、そのまま段階Bで拡張できます**（作り直す必要はありません）。

## 5. 先行体験 — 採点と問題文をタスク1だけ試す（推奨）

土台機能（類題ボタン等）や全タスクの完成の **前に**、採点と問題文の流れをタスク1だけ先に体験します。

### 5.1 この段階でやること / やらないこと

| やること | やらないこと |
|----------|--------------|
| 類題 Excel を1問分用意（または教材のまま試す） | 全10タスクの類題判定を一度に作る |
| `ExcelChecker*_PV1.cs` を **新規作成**（タスク1だけ類題ロジック） | Terminal で Checker を複製 |
| タスク2以降は **教材 Checker に委譲** | 類題ボタン・モード切替の実装 |
| `MOS演習問題文一覧.json` の **taskId:1 だけ** 類題文言に更新 | 問題文 JSON の taskId:2 以降の変更 |
| `config.json` の `library` を一時変更 | ランチャー側 config の変更 |
| VS でタスク1の採点・問題文表示を確認 | 全タスク分の問題文 JSON の差し替え |

### 5.2 誰が何をするか（先行体験）

| Step | 内容 | 担当 |
|------|------|------|
| A-1 | 類題用 Excel（タスク1分）を用意 | 教材担当者 |
| A-2 | タスク1の類題問題文・正解条件の要点を決める | 教材担当者（Cursor に文案提案を依頼してもよい） |
| A-3 | 類題 Checker を新規作成（**タスク1のみ**類題判定） | **Cursor に依頼** |
| A-4 | `MOS演習問題文一覧.json` の **projectId:1 / taskId:1** だけ類題文言に更新 | **Cursor に依頼** |
| A-5 | `config.json` の `library` を `_PV1` に変更 | **Cursor に依頼** |
| A-6 | VS でタスク1の問題文表示・採点を確認 | 教材担当者 |

※ taskId:2 以降の問題文は §7 の段階Bで揃えます。

### 5.3 プロジェクト1で試す場合の具体例

§3.1 の表より:

| 項目 | 値 |
|------|-----|
| Excel | `Tab1\Initial\project1.xlsx` |
| 参照元 Checker | `ExcelChecker1_2.cs` |
| 新規作成 | `ExcelChecker1_2_PV1.cs` |
| 類題化するメソッド | `CheckTask_1_2_01` のみ |
| 委譲するメソッド | `CheckTask_1_2_02` 〜 `05` → 教材 `ExcelChecker1_2` を呼ぶ |
| config 変更 | `"1"` の `library` → `ExcelChecker1_2_PV1` |

### 5.4 Cursor に依頼する内容（概要）

実行プロンプト **§1「先行体験プロンプト」** を Agent モードで貼ります。

Cursor が行うこと:

1. `ExcelChecker1_2_PV1.cs` を **新規作成**（`ExcelChecker1_2.cs` を参照、Terminal 複製なし）
2. `CheckTask_1_2_01` だけ類題の正解条件に合わせて実装
3. 他タスクは教材 Checker の同名メソッドを呼び出して委譲
4. `MOS演習問題文一覧.json` の **projectId:1 / taskId:1** の `description` だけ類題文言に更新
5. `config.json` の project `"1"` の `library` を `ExcelChecker1_2_PV1` に変更
6. Debug ビルド

### 5.5 VS での確認（先行体験）

1. `MOSapp.slnx` を VS で開き、Excel 採点アプリを **Debug 実行**
2. 「採点ボタンの表示」にチェック
3. 演習タブから **プロジェクト1** を開く
4. アプリバーに **タスク1の類題問題文** が表示されているか確認
5. **タスク1だけ** 類題どおりに操作 → **採点** → タスク1が **〇** になるか
6. タスク1を未操作のまま（または不正解のまま）→ タスク1が **✖** になるか

※ タスク2以降は教材の判定のままなので、類題化していなくても動作します。

### 5.6 先行体験のチェックリスト

- [ ] `ExcelChecker1_2_PV1.cs` が新規追加されている
- [ ] 教材の `ExcelChecker1_2.cs` は変更されていない
- [ ] `MOS演習問題文一覧.json` の **taskId:1 だけ** 類題文言になっている
- [ ] アプリバーに類題の問題文が表示される
- [ ] `config.json` の `library` が `ExcelChecker1_2_PV1` になっている
- [ ] Debug ビルドが通る
- [ ] タスク1で意図どおり **〇/✖** が返る

### 5.7 次のステップ

先行体験ができたら **§7（本番作業）** に進み、残りのタスク・問題文 JSON（taskId:2 以降）を揃えます。

## 6. 名前の付け方

### 6.1 Checker（採点プログラム）

Checker のクラス名は **必ず `ExcelChecker` で始めてください。**  
アプリがこの名前で探しに行きます。

類題 Checker 名は、**教材 Checker 名の末尾に `_PV1`（類題1）を付ける** 形にします。

| 例（プロジェクト1） | 名前 |
|---------------------|------|
| 教材 Checker | `ExcelChecker1_2` |
| 類題1 Checker | `ExcelChecker1_2_PV1` |

- `_PV1` … Practice Variant 1（類題1）
- 全プロジェクトの対応は **§3 の表** を参照

各タスクのメソッド名は教材と同じ形にします（例: プロジェクト1なら `CheckTask_1_2_01`）。

### 6.2 問題文 JSON

| 用途 | ファイル名 |
|------|------------|
| アプリが読むファイル | `MOS演習問題文一覧.json` |
| 類題1の原稿（任意） | `MOS演習問題文一覧_PracticeVariant1.json` |
| 類題2の原稿（任意） | `MOS演習問題文一覧_PracticeVariant2.json` |

## 7. 本番作業 — 1プロジェクトを仕上げる手順

**§5 の先行体験のあと**に進めます。  
最初は **プロジェクト1だけ** で試し、問題なければプロジェクト2、3…と順に広げます。

先行体験で作った `ExcelChecker1_2_PV1.cs` がある場合は、**タスク2以降の委譲をやめ、各タスクを類題用に書き換えていきます**。

### 誰が何をするか

| Step | 内容 | 担当 |
|------|------|------|
| 1 | Excel を類題用に編集 | 教材担当者（Excel で編集） |
| 2 | 類題 Checker を **新規ファイル** で作成 | **Cursor に依頼** |
| 3 | config.json の `library` を変更 | **Cursor に依頼**（または指示どおり確認） |
| 4 | 問題文 JSON を更新 | **Cursor に依頼** |
| 5 | VS で採点確認 | 教材担当者（アプリを起動して確認） |

Checker は **Terminal でファイルを複製しない** でください。  
教材 Checker（例: `ExcelChecker1_2.cs`）の内容を **参照** し、**新しいファイル**（例: `ExcelChecker1_2_PV1.cs`）として Cursor に作成させます。  
どのファイルを参照したかは、Cursor の完了報告で確認します。

### Step 1 — Excel を用意する（手作業）

1. `Tab1\Initial\project1.xlsx` を開く（または類題用に編集したファイルをここに置く）
2. 類題用のシート内容に編集する
3. リセット確認もするなら、`Tab1\Templates\project1.xlsx` も同様に揃える

### Step 2 — Checker を作る（Cursor に依頼）

実行プロンプト（`Excel_類題実装_実行プロンプト.md`）を Cursor に貼って依頼します。

Cursor が行うこと:

1. §3 の表から **参照元** を決める（プロジェクト1 → `ExcelChecker1_2.cs`）
2. **`ExcelChecker1_2_PV1.cs` を新規作成**（既存ファイルの上書きや Terminal での copy はしない）
3. クラス名を `ExcelChecker1_2_PV1` にし、類題の正解条件に合わせて各タスクの判定を修正
4. 必要なら `.csproj` に Compile 追加
5. Debug ビルドしてエラーがないことを確認

### Step 3 — config.json で Checker を切り替える（Cursor に依頼）

`MOSapp/mos_xaml_app/Assets/config.json` のプロジェクト1の `library` を変更します。

```json
"1": {
  "taskCount": 5,
  "library": "ExcelChecker1_2_PV1",
  ...
}
```

※ 編集するのは **`mos_xaml_app` 側** の config です。  
`MOSapp/MOSapp/Assets/config.json`（ランチャー用）ではありません。

### Step 4 — 問題文 JSON を合わせる（Cursor に依頼）

1. `MOS演習問題文一覧.json` のプロジェクト1を類題用文言に更新
2. 原稿用に `MOS演習問題文一覧_PracticeVariant1.json` を新規作成してもよい

### Step 5 — VS で動作確認する（手作業）

1. `MOSapp.slnx` を VS で開く
2. Excel 採点アプリ（`mos_xaml_app`）を **Debug 実行**
3. メイン画面で **「採点ボタンの表示」** にチェックを入れる
4. 演習タブからプロジェクト1を開く
5. 問題文が類題になっているか見る
6. 正しい操作をしたあと **採点** → 全部 **〇** になるか
7. **リセット** して何もせず **採点** → 全部 **✖** になるか

## 9. 破壊的操作について（採点が思ったより厳しいとき）

採点は2段階です。

1. **Checker** … Excel の状態が正しいか見る
2. **破壊的操作のチェック** … Excel 操作ログを見て、余計な操作があれば **✖** にする

ポイント:

- 破壊的操作のチェックは、**教材 Checker でも類題 Checker でも同じ** です（プロジェクト番号・タスク番号で決まる）
- 「タイトルスタイル → 見出し1」のような、近い操作の類題なら、厳しい設定以外ではあまり邪魔になりにくい
- 確認前に **リセット** して、余計な操作ログを残さない

詳しくは `tasks/Excel_破壊的操作検知_方針とログ拡張.md` を参照。

## 10. うまくいかないとき

| 症状 | よくある原因 | 対処 |
|------|--------------|------|
| 古い Excel が開く | `Tab1\Initial` の中身が更新されていない | Initial のファイルを確認 |
| 教材の採点のまま | `library` を変えていない / ビルドしていない | config 確認 → 再ビルド → アプリ再起動 |
| 問題文が変わらない | JSON を保存していない | JSON 保存 → アプリ再起動 |
| 正解なのに ✖ | 破壊的操作ログ | リセットして、必要な操作だけやり直す |
| Checker が見つからない | クラス名が `ExcelChecker` で始まっていない | §6.1 の命名に従う |
| 採点ロジックが合わない | プロジェクト番号と Checker を取り違え（例: P1 に `1_1` を使った） | §3 の表を確認 |

## 11. Cursor に類題「作成」を依頼するとき

アプリ本体（類題ボタン等）の改修は **依頼しない** でください。  
Cursor には、次の **コンテンツ作成** だけを依頼します。

- 類題用 Checker（`ExcelChecker*_PV*.cs`）の **新規ファイル作成**
- 類題用問題文 JSON の作成・修正
- `config.json` の `library` 一時変更（確認用）
- Debug ビルドと、§8 チェックリストに沿った確認

### Checker 作成の進め方（重要）

| やること | やらないこと |
|----------|--------------|
| 教材 Checker を **読んで参照** する | Terminal で `copy` / `cp` してファイルを複製する |
| **新しい .cs ファイル** として類題 Checker を書く | 教材 Checker のファイル名をそのまま上書きする |
| 完了報告に「参照したファイル」「新規作成したファイル」を書く | 人間に「どのファイルを複製するか」を判断させる |

Excel の編集は、基本的に教材担当者が Excel で行います（Cursor に任せる場合は明示的に依頼してください）。

コピペ用プロンプトはこちらです。

- `tasks/Excel_類題実装_実行プロンプト.md`
