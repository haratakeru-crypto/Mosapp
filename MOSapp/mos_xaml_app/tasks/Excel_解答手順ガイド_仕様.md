# Excel 解答手順ガイド — 仕様

苦手・わからない学生向けに、アプリバー＋Excel を操作しながら **紙芝居形式で解答手順（画像＋短い文言）を1ステップずつ確認できる**機能の仕様。  
対象アプリ: `mos_xaml_app`（MOS Excel 模擬アプリ）。対象課題: **Group1（演習）のみ**。

採点後の「詳細理由」（`ExcelScoreExplanation`）や、採点結果の解答例 PNG（`References/Answers/...`）とは **別機能**。

---

## 0. 目的と非目的

### 目的

- 問題文だけでは操作イメージが湧かない学生が、**見ながら Excel を操作**できるようにする。
- 手順は文字だけでなく、PDF 由来の **切り出し画像**を主とし、教科書的に使えるようにする。
- 手順ウィンドウは Excel の上部に重ねて表示し、利用者が見やすい位置へ移動できるようにする。限られた表示領域でも読めるよう、**1タスク1枚の縮小表示は避け**、操作単位に分割した画像を紙芝居表示する。

### 非目的（当面やらないこと）

- Group2 / Group3 / 模試 PDF の投入（渡さない前提）。
- アプリ実行時に PDF を直接開いて表示すること（ランタイム PDF ビューアは使わない）。
- 採点ロジックや正誤判定の変更。
- 既存の類題 `answerSteps`（JSON 全文表示）や採点後 `TaskN.png` 解答例の置き換え。

## 1. 用語

| 用語 | 意味 |
|------|------|
| **解答手順ガイド** | 本機能全体。選択画面のオプションで有効化し、AppBar から開く。 |
| **手順ウィンドウ** | モードレスの紙芝居 UI。Excel 操作を妨げない。 |
| **タスク** | プロジェクト内の1問。PDF では原則 **1ページ＝1タスク**。 |
| **ステップ** | 紙芝居の1枚。1タスクのページ内を操作単位に分割したもの（画像＋キャプション）。 |
| **ガイド資産** | 分割後の PNG と `manifest.json`。アプリが読み込む実体。PDF 本体は配布物に含めない想定。 |

## 3. UI / 挙動仕様

### 3.1 プロジェクト選択画面（`MainWindow`）

- 既存の「採点ボタンの表示」「類題ボタンの表示」と同列にチェックボックスを追加する。
- プロパティ例: `ShowAnswerGuide`（`bool`、デフォルト `false`）。
- ON のときだけ、当該セッションの AppBar に「手順」を出す。
- プロジェクト開始後の動的トグルは必須ではない（選択画面で決める運用でよい）。必要なら後続で対応可。

### 3.2 AppBar（`AppBarWindow`）

- 次の条件をすべて満たすときだけ「手順」ボタンを表示する。
  - `ShowAnswerGuide == true`
  - Group1 の通常教材である
  - 類題モードではない
  - 単語帳モードではない
- 表示判定用プロパティ例: `ShowAnswerGuideEffective`。
- クリックで手順ウィンドウを開く（既に開いていれば前面化、またはタスク一覧に戻す）。
- ガイド表示中フラグ例: `IsAnswerGuideOpen`（採点の `IsScoreResultOpen` とは別）。

### 3.3 手順ウィンドウ（新規・モードレス）

必須:

- **`Show()`（モードレス）**。`ShowDialog()` は使わない。
- Excel の上部に重ねて表示し、Excel を縮小・横分割しない。
- 初期位置は Excel ウィンドウ上部（右上寄りを推奨）とし、タイトルバーのドラッグで自由に移動できるようにする。
- `Topmost = true` とし、Excel を操作している間も手順が背後に隠れないようにする。
- ただし、採点結果ダイアログのような `Deactivated` 時の再アクティブ化、定期的な `SetForegroundWindow`、自動的な `Activate()` は行わない。「手順」ボタンを明示的に押して既存ウィンドウを呼び戻す場合だけ前面化してよい。  
  → **常に見えるが、入力フォーカスは Excel に渡せる**状態にする。
- リサイズ可・画像領域はスクロール可とする。ユーザーが移動・リサイズした位置と大きさは、少なくとも当該セッション中は保持する。
- 「画面調整」を実行しても Excel は従来どおりのサイズに戻し、手順ウィンドウは画面内に収まるよう位置だけ補正する。
- 表示内容:
  - 大きなステップ画像
  - 短いキャプション（1〜2行）
  - 進捗（例: 2/5）
  - **次へ / 戻る / タスク一覧へ / 閉じる**
  - **幅に合わせる / 100% 表示**（画像が小さくなりすぎる場合に切り替える）

任意（初期は簡易で可）:

- キーボード左右で次へ／戻る。
- 拡大／縮小ボタン。

### 3.4 アプリバー操作の抑止（ガイド表示中）

| 操作 | ガイド表示中 | 採点ダイアログ表示中 |
|------|----------------|----------------------|
| Excel 本体の操作 | **可能** | 従来どおり（前面奪い等で実質しづらい。閉じるまで優先） |
| 終了 | **無効** | 無効（既存） |
| リセット | **無効** | 無効に揃える（ガイド導入時に明示的に抑止） |
| レビューページ | **無効** | 無効（既存） |
| 次のプロジェクト | **無効** | 無効（既存） |
| 採点 | **有効** | （結果表示中は既存の CanExecute） |
| 手順 | トグルで閉じる／前面化 | 採点中は無効でも可 |

操作ロックは個別実装にせず、次の統合状態で判定する。

```text
IsNavigationLocked =
    IsAnswerGuideOpen
    || IsScoring
    || IsScoreResultOpen
```

- ガイド表示中でも許可する AppBar 操作:
  - 採点
  - 手順ウィンドウの前面化／閉じる
  - 前／次タスク、タスク番号
  - 解答済み、あとで見直す
  - 画面調整
- ガイド表示中は無効にする AppBar 操作:
  - 終了
  - リセット
  - レビューページ
  - 次のプロジェクト
  - 教材／類題の切替
- 一時停止ボタンを将来表示する場合は、ガイド表示中も利用可能とする。
- XAML の `IsEnabled` / Command の `CanExecute` だけに頼らず、終了・リセット・レビュー等のクリック処理側にも同じガードを入れる。

採点を押したとき:

1. `IsScoring = true` にして、採点以外の危険な操作を引き続きロックする。
2. 手順ウィンドウを閉じる（初期実装では自動再開しない）。
3. 採点〜結果ダイアログは既存フローのまま（`ShowDialog` ＋ 既存の前面維持）。
4. 採点結果を閉じて `IsScoring = false` になったあと、必要なら「手順」を再クリックして再開できる。

タイマーが満了したとき:

- ガイドを閉じてから、通常の試験終了処理へ進む。
- ガイド表示を理由にタイマー満了を保留しない。

### 3.4a 操作連動（隔離ブランチ）

**本線（`procedure`）は切り取り・紙芝居 UI のみ。** 操作連動の実装・detect 付き manifest は **`procedure-sync` ブランチに隔離**する（優先順位: Excel 切り取り → Word → PPT → 連動の後追い）。

手順ステップに任意の `detect` を付け、Excel 状態が条件を満たしたら同一タスク内で次ステップへ進む（単語帳タブ連動に近い）。実装は `GuideStepSyncController`（`procedure-sync` 側）。

| detect | 意味 |
|--------|------|
| `Sheet:試験結果` | アクティブシート名が一致 |
| `TableSelected` | 選択範囲がテーブル（ListObject）内 |
| `BandingRowOffColOn:試験結果` | 指定シートのテーブルで縞模様（行）オフかつ（列）オン |
| `LastColumnOn:試験結果` | 指定シートのテーブルで［最後の列］オン |

- ステップ入場時に条件が**未達**なら連動オン（達成で次へ）。**既に達成済み**なら連動オフ（手動の次へ。選び直し不要）。
- AppBar の作業タスクは自動では切り替えない。
- 最終ステップ（完成）には detect を付けない。
- すべてのステップに連動を付けなくてよい（**部分連動**可）。流れで既に満たしやすい操作は detect を外し、変化が必要な操作や「未達時だけ助けたい」操作に付ける。
- パイロット実績:
  - **Project1 Task1**: シート → テーブル選択 → 縞模様完了まで連動
  - **Project1 Task2**: step1（シート）・step2（テーブル選択）のみ。step3（最後の列）は手動。テキストのみの操作1画像は Task1 step01 を流用可

#### 検知の仕組み（メモ）

- 連動は Excel イベント常時購読ではなく、**ガイド表示中かつ当該ステップに `detect` があるときだけ** `DispatcherTimer`（約 400ms）で COM 状態をポーリングする。
- 監視対象は「今のステップの detect 条件」に限定する（シート／リボンを触っても、条件達成以外ではステップは進まない）。

#### ログ（将来・優先度低）

**操作連動の本実装・安定化のあと**で検討する（切り取り → Word → PPT → 連動 → 本ログ、の後段）。

| 方針 | 内容 | 備考 |
|------|------|------|
| A. ステップ進行のみ | ステップが進んだときだけ記録 | 軽量。成功経路の確認向き。**detect 外の誤操作は取れない** |
| B. ガイド表示中の限定イベント | シート名変更・テーブル選択の有無・対象 detect の成否など種類を絞る | 誤操作の手がかりになりつつ膨張を抑えやすい |
| C. サンプリング | 数秒に1回、現在シート／選択概要だけ | 連続クリックでも行数が頭打ち |
| D. リングバッファ | 直近 N 件をメモリ保持し、必要時だけファイルへ | 普段の I/O ほぼゼロ |

- シート切替・リボン操作など「状態変化すべて」を無制限にファイルへ書くと、操作が多い学習者ほどログが膨れ、ディスク I/O で重くなりうる → **初期採用しない**。
- 「進行だけ」は軽いが、手順にない誤操作の分析には弱い。「誤操作も見たい」なら全イベントではなく **B または D（ガイド中・種類限定・件数上限）** が現実的。

### 3.5 タスク切替のアナウンス

作業中タスク（AppBar）と、手順ウィンドウで見ているタスクがずれる場合がある。

- **AppBar のタスク切替では確認しない**（ガイドは自動追従しない）。
- 手順を開いた直後は、AppBar の現在タスク手順があればそのステップ1を表示する（一致のため確認なし）。資産がなければタスク一覧。
- **タスク一覧から別タスクを選ぶとき**、および **次へ／戻るでタスク境界を跨ぐとき**、行き先の手順が AppBar と異なる場合は確認する。  
  例: **「アプリバーはタスク1です。タスク2の手順を表示しますか？」**  
  - はい → そのタスクへ（次へならステップ1、戻るなら最終ステップ）  
  - いいえ → いまの手順のまま  
  - 行き先が AppBar と一致しているときは確認しない  
- AppBar は自動では切り替えない（作業タスクの切替は学生自身が行う）。  
  - 最終ステップの次へ → 次タスクへ（次タスクがなければ無効）  
  - 先頭ステップの戻る → 前タスクへ（前タスクがなければ無効）

## 4. コンテンツ仕様

### 4.1 元データ（入力）

| 項目 | 内容 |
|------|------|
| 対象 | **Group1 のみ** |
| 単位 | **プロジェクトごと 1 PDF** |
| ページ構成 | 原則 **1ページ＝1タスク**。ページ内にそのタスクの操作手順がすべて載っている |
| 受け渡し | 開発時に PDF を渡す → 分割 → ガイド資産としてリポジトリへ配置。PDF 自体はアプリ実行時に必須としない |

### 4.2 分割方針（見やすさ優先）

手順ウィンドウは Excel 上に重ねるコンパクトな表示となるため、**タスクページをそのまま1枚表示して縮小するのは採用しない**。

- 1ステップ ＝ 画面上でひとまとまりの操作（シート選択、タブ、ボタン、値入力など）。
- 画像は全体縮小より **該当 UI 付近の切り出し・拡大**を優先し、狭い手順ウィンドウでも読めるようにする。
- キャプションは短く（長い説明は画像側に任せる）。
- 分割境界の最終判断は、最初の1プロジェクトで粒度を合わせ、以降は同ルールで量産する。

#### Project1 切り出しメモ（`_source/split_project1.py`）

- 左右: 奇数タスク `X0=285`、偶数タスク `X0=334`（PDF が交互に寄る。偶数は破線・☝を避け「操作」文字手前）。右端は共通 `X1=1175`。
- 上下: OCR の「操作N」「完成」Y を境界にし、見出し上余白・次見出し前ギャップで切る。
- 元PDFに画面がなくテキストだけの操作（例: 1-2 操作1）は、同趣旨の既存ステップ画像を**ファイルコピーで流用**してよい（例: Task1 `step01` → Task2 `step01`）。

### 4.3 ガイド資産の配置

採点用解答例（`References/Answers/Group1/...`）とは **別フォルダ**にする。

```
References/GuideSteps/Group1/Project{N}/Task{T}/
  step01.png
  step02.png
  ...
  manifest.json
```

`manifest.json` 例:

```json
{
  "groupId": 1,
  "projectId": 1,
  "taskId": 3,
  "steps": [
    {
      "image": "step01.png",
      "caption": "「売上一覧」シートを選ぶ"
    },
    {
      "image": "step02.png",
      "caption": "ページレイアウト → 印刷の向き → 横"
    }
  ]
}
```

規約:

- `step` ファイル名はゼロ埋め2桁以上（`step01`, `step02`, …）。
- `manifest.json` の `steps` 順が紙芝居の順番。画像ファイルのソートだけに頼らない。
- あるタスクにフォルダ／manifest が無い場合、タスク一覧に出さない（または「準備中」表示。初期は **出さない** でよい）。
- プロジェクトにガイド資産が1件も無い場合、「手順」押下時に「このプロジェクトの手順はまだありません」と案内する。
- `groupId` / `projectId` / `taskId` が現在のプロジェクトと一致しない manifest は読み込まない。
- 画像パスは manifest と同じタスクフォルダ内の相対ファイル名のみ許可し、絶対パスや `..` を許可しない。
- manifest の破損や画像欠落があってもアプリ全体を終了せず、そのタスクだけを一覧から除外してデバッグログへ理由を記録する。
- 画像はファイルロックを残さない読み込み方式（例: `BitmapCacheOption.OnLoad`）を使用する。

### 4.4 ビルド・発行への収録

本プロジェクトは旧形式の `.csproj` で配布資産を明示しているため、`GuideSteps` を作成するだけでは出力・発行物に含まれない。

- `MOSExcelMogiApp.csproj` に `References\GuideSteps\**\*.json` と `References\GuideSteps\**\*.png` を Content として追加する。
- `CopyToOutputDirectory` は `PreserveNewest` とする。
- 後から追加する Project2 以降も自動的に含まれるよう、プロジェクト単位の個別列挙ではなくワイルドカードを使う。
- Debug 出力と ClickOnce 発行物の両方にガイド資産が含まれることを確認する。

### 4.5 CSV / 既存資産との関係

| 資産 | 役割 |
|------|------|
| PDF → 分割した GuideSteps | **本機能の本体**（画像紙芝居） |
| CSV `解答操作`（`解答手順あり模擬試験①問題文.csv` 等） | 分割時のキャプションたたき台／将来の文字フォールバック。初期実装では画像必須でよい |
| 類題 JSON `answerSteps` | 類題モードの既存機能。本ガイドとは別 |
| `References/Answers/.../TaskN.png` | 採点結果からの解答例表示。本ガイドとは別 |

## 5. 実装方針（骨組みとコンテンツの分離）

### 5.1 フェーズ0 — 骨組み（一括実装）

データが無くても動く骨格を先に入れる。

1. 選択画面チェック `ShowAnswerGuide`
2. AppBar「手順」の表示制御
3. モードレス手順ウィンドウ（タスク一覧 → 紙芝居）
4. Excel 上部への初期配置、移動・リサイズ、受動的な `Topmost`
5. `IsAnswerGuideOpen` / `IsScoring` / `IsScoreResultOpen` による統合操作ロック
6. 採点との共存（採点時はガイドを閉じ、採点中の操作ロックを維持）
7. 手順オープン／タスク一覧選択時の不一致アナウンス、次へ／戻るのタスク跨ぎ
8. `References/GuideSteps/Group1/ProjectN/TaskT/manifest.json` の読み込み
9. `.csproj` へのガイド資産の収録

ダミー資産（1タスク分のプレースホルダ）を置いて UI 検証してもよい。

### 5.2 フェーズ1〜 — プロジェクトごとのコンテンツ

推奨の進め方は **切り取りを先に一通り進め、操作連動は後から（または区切りごとにまとめて）載せる**。

理由:

- 切り取り（見え方・奇数偶数の X・操作境界）と連動（検知可否・入場時の達成済み）は判断軸が違う。
- 連動はタスクごとにフル／部分／detect なしが変わりうる。画像が揃ってからの方が横断で設計しやすい。
- 切り取りは量産向き。連動は Excel での検証が要り、タスク単位だと切り替えコストが大きい。

例外: コマ分割が連動前提で決まる特殊タスクだけは、切り取り前に detect 案を一行書いてから切る。

作業手順:

1. **PDF 渡し** — `Group1_Project{N}.pdf`（ページ順＝タスク順の確認）
2. **切り取り（優先）** — ページ＝タスク確認 → 操作番号境界で PNG 分割 → 見た目レビュー（破線・☝の有無を奇数偶数ルールで揃える）→ `GuideSteps/.../TaskT/` 配置
3. **表示確認** — 骨組みから紙芝居として通す（連動なしでも可）
4. **detect 表** — タスク×ステップで付ける／付けないを一覧化（部分連動を前提）
5. **操作連動** — `manifest` に `detect` を付与 → 未達オン／達成済みオフを実機確認
6. 次のプロジェクトへ（または同一プロジェクトの残りタスクへ）

パイロット: **Project1 Task1・Task2** で切り取りの型と連動の型を確定済み（連動コードは `procedure-sync`）。本線では Task3〜の**切り取り**を優先し、連動は後追いで `procedure-sync` に載せる。

### 5.3 技術メモ（既存コードとの接点）

| 既存 | 本機能での扱い |
|------|----------------|
| `ScoringResultDialog` の `ShowDialog` ＋前面固定 | **マネしない**。ガイドはモードレス・非奪フォーカス |
| `IsScoreResultOpen` / `ApplyScoreResultActionState` | `IsAnswerGuideOpen` と `IsScoring` を追加し、統合状態で抑止を拡張 |
| `AnswerStepsWindow` | 類題用の全文＋モーダル。ガイド用は **新規ウィンドウ**推奨 |
| `ImageWindow` | 採点後の1枚表示用。ガイドの紙芝居には流用してもよいが、次へ／戻るがある専用 UI の方がよい |
| `ExcelStartupInputGate` / `EnableWindow` | ガイド表示のために Excel を無効化しない |
| `PositionExcelWindow` | ガイド表示のために Excel のサイズは変更しない。ガイドだけを Excel 上部へ重ねる |

## 6. 受け入れ条件（骨組み）

- [ ] チェック OFF では「手順」が出ない
- [ ] チェック ON かつ Group1 通常教材で AppBar に「手順」が出る
- [ ] 類題・単語帳では「手順」が出ない
- [ ] 手順ウィンドウ表示中に Excel でセル入力・リボン操作ができる
- [ ] Excel を操作しても手順ウィンドウが背後に隠れず、フォーカスを奪い返さない
- [ ] 手順ウィンドウをドラッグ移動・リサイズできる
- [ ] Excel ウィンドウの大きさはガイド表示前後で変わらない
- [ ] 同表示中、終了・リセット・レビュー・次のプロジェクトが押せない
- [ ] 同表示中、教材／類題を切り替えられない
- [ ] 採点は押せ、採点処理中も危険操作が無効のまま維持され、結果ダイアログ表示中は従来どおり結果が優先される
- [ ] タスク一覧・次へ／戻るで AppBar と異なるタスクへ進むと確認が出る（一致時・AppBar 切替では出ない）
- [ ] 次へ／戻るでタスク境界を跨げる（最終タスクの最終では次へ無効）。AppBar は自動切替しない
- [ ] ガイド資産があるタスクだけ一覧に出る
- [ ] 次へ／戻るでステップが切り替わり、画像とキャプションが対応する
- [ ] ズーム（プリセット／任意％）で表示倍率を変えられる
- [ ] タイマー満了時はガイドが閉じ、通常の試験終了処理が行われる
- [ ] manifest破損や画像欠落があってもアプリ全体が終了しない
- [ ] Debug 出力と ClickOnce 発行物にガイド資産が含まれる
