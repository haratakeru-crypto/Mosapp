# 採点・起動・プロジェクト切り替え・安定性の修正まとめ

## 1. 一括採点の試行番号

- 原因: Word と Excel は採点時の試行番号を 0 のまま見ており、復習後にやり直しても、選び直して一括採点すると最初の結果を見ていた。
- 対応: PowerPoint と同じく、結果画面からやり直したタスクだけ試行番号を上げ、その番号の記録を採点する。

## 2. その場採点の速度

- 原因: PowerPoint は採点のたびに広い破壊的操作チェックをしていた。Word も同様の待ちがあった。
- 対応: 採点対象のタスクだけを確認する。Excel にも、採点したタスクに限った破壊的操作チェックを追加した。

## 3. 採点中ダイアログと連打

- 原因: Word と PowerPoint は採点中表示がなく、連打で採点が重なった。PowerPoint は表示してもバーが動かなかった。
- 対応: Excel、Word、PowerPoint とも、採点中はダイアログを出し、完了まで再クリックを無視する。PowerPoint のバーも動くようにした。

## 4. 起動時に操作を受け付けない処理

- 原因: Office を早く表示すると、アドインが記録を始める前に操作でき、ログが残らず×になることがあった。Word の初回修正では準備中ダイアログが出ない差もあった。
- 対応: 3科目とも、起動後は「準備中です」で入力を止め、アドインの準備ができてから操作できるようにした。

## 5. 次のプロジェクトの表示

- 原因: Word は青帯、Excel は案内なし、PowerPoint は遅れて緑帯だった。
- 対応: 300ミリ秒未満なら案内を出さず、超えたときだけ文字だけの案内にする。Word と Excel を PowerPoint に合わせた。

## 6. Word の次プロジェクトが約5秒かかる

- 原因: 切り替えのたびに初回起動用の処理へ入り、Word の再起動と 3秒・2.5秒の待ちが発生していた。通常スレッドから Word を操作していたため、接続に失敗して同じ待ちに戻ることもあった。
- 対応: 起動済みの Word を専用スレッドで再利用し、文書の保存・閉じ・次文書の表示だけを行う。失敗したときだけ初回起動の処理へ戻す。開けるまでプロジェクト番号は進めず、切り替え中の再クリックは無視する。

## 7. PowerPoint の次プロジェクト連打

- 原因: 切り替え中にもう一度押すと処理が重なった。Excel と Word には防止があった。
- 対応: PowerPoint も切り替え中の再クリックと、5分タイマーとの同時発生を無視する。

## 8. Excel のプロジェクト10でアプリが落ちる

- 原因: レビューページへ移るとき、通常スレッドが UI 側の Excel 参照を操作・解放していた。連打で同じ終了処理が重なると、無効なブック位置の参照と使用中参照の解放が起きた。
- 対応: Excel の保存と終了を専用スレッドの一回の処理にまとめた。共有参照は渡さない。プロジェクト10とレビューボタンの連打は無視する。

## 9. PowerPoint プロジェクト1で、1-8のあと1-7以外が×

- 原因: 1-8でスライド2に1枚入ると、後ろのスライド番号が1つずれる。採点側はその補正を、証跡 `[Task1-8] SummaryZoom` があるときだけ行う。証跡はタイトル「ご提案のポイント」も条件だったため、タイトルを付け忘れると補正されず、1-2から1-6が挿入前の番号を見た。スライド1を見る1-7だけ○だった。
- 対応: リンク先が「1.教育理念」と「4.募集要項」の2件だけなら、タイトルがなくても証跡を記録する。タイトルの有無は1-8の採点だけが見る。

## 10. Word のプロジェクト6と9が重い

- 原因: いちばん大きかったのは、開発用アドインと製品用アドインが同時に載り、処理が二重になっていたこと。加えて、プロジェクト6は表、プロジェクト9は変更履歴付きの文書で Word 本体も重い。アドインの編集中確認（約6秒ごとの XML 読み取り、約1.2秒ごとの画面更新切り替え、ナビの常時確認など）が重なり、表や変更履歴が多いほど遅く感じられた。
- 対応: 開発時は製品用アドインを無効にし、どちらか一方だけが載るようにした（詳細は14）。そのうえで、XML 読み取りは透かしなどが問題になるプロジェクト4などに限定し、プロジェクト6と9では編集中の確認と画面更新の切り替え、ナビの常時確認を止めた。ナビを閉じる依頼そのものは残している。採点時の破壊操作確認は維持。文書自体の重さは残るため、他プロジェクトと完全同等にはならない。

## 11. PowerPoint で8番のタスクボタンが出ない

- 原因: 試験バーのボタンは1から7までが画面に固定で、8以降だけをコードで後から追加していた。追加のタイミングがずれると8が出ない。ボタン幅の合計がバーを超えるとはみ出して見えなくなる。8問未満のプロジェクトでは、もともと8は出さない。
- 対応: 8番目も1から7と同じ固定ボタンにし、初期状態は非表示にした。そのプロジェクトのタスクが8個以上のときだけ表示する。9番目以降は、必要なときだけ追加する。

## 12. 複数起動の防止

- 原因: 起動が重いときにアイコンを連打すると、同じ模試アプリが複数起動していた。科目ごとに単一起動の仕組みがなく、AppBar や Office も二重に残りやすかった。
- 対応: Word、Excel、PowerPoint それぞれに科目専用の Mutex を入れた。2つ目以降は起動しない。すでに開いていればそのウィンドウを前面に出し、まだ起動中なら「既に起動しています」と案内する。Mutex 名は科目ごとに分けているため、Word を開いたまま Excel を開くことはできる。

## 13. 終了時にアプリが残る

- 原因: 終了確認だけでは、試験バーや Word、PowerPoint が閉じきらず、exe や Office プロセスが残った。サインアウト時にユーザー切り替えを妨げることがあった。Excel には終了時の片付けがあったが、Word と PowerPoint は弱かった。
- 対応: 終了時に試験バーを閉じ、文書を保存して Office を Quit し、COM 参照を解放する。Quit 後もプロセスが残る場合は待ってから強制終了する。Word、Excel、PowerPoint の3科目に同様の終了片付けを入れた。受験者登録用の MosPracticeSessionWatch は学生配布に未実装のため、今回の対象外とした。

## 14. Word のハイブリッド起動

- 原因: プロジェクトを開くたびに VSTO 心拍待ちと Word 再起動が入り、初回も切り替えも重かった。Excel のように先に開く経路がなく、待ちが UI を止めていた。
- 対応: VSTO 心拍が新しければ既存 Word をそのまま使い、すぐ文書を開く。未準備のときだけ再起動する。コールド起動は空起動ではなく文書付き起動とし、COM 拒否時はリトライする。開けなければ試験バーへ進まない。

## 15. Word の保護ビュー自動解除

- 原因: 文書付き起動やコピー経路によって、Word が保護ビューで開くことがあった。その状態では通常の文書一覧に載らず、アプリは「開けなかった」と判断して試験バーに進まなかった。
- 対応: オープン前にインターネット由来マークを除去する。保護ビューで開かれた場合は「編集を有効にする」相当の処理で通常編集に切り替え、成功扱いにする。Excel と同じ考え方。

## 16. Word の準備中ダイアログ表示

- 原因: 項目4の共通対応だけでは、プロジェクト選択や次プロジェクト移動のとき、Word 起動画面の後にダイアログが出て「準備中」の意味を果たしていなかった。プログレスバーも UI スレッド待ち中は動かなかった。
- 対応: クリック直後から専用スレッドで準備中画面を前面表示する。Word の処理中もマーキーアニメで動きを見せる。準備中は Word を非表示で開き、完了後に表示する。次プロジェクト移動でも保存から開き直しまで同じダイアログを出す。

## 17. PowerPoint の準備ゲート（心拍待ち）

- 原因: PowerPoint は起動は速いが、アドイン準備の待ちが弱く、記録開始前に操作や採点が進むとログが残らず全問×になりやすかった。Wi-Fi より、ローカルで VSTO が追いついていないタイミングが疑わしい。
- 対応: 起動経路はそのままに、心拍で「アドインが動いている」ことを確認してから操作を許可する。準備中ダイアログを出し、未準備のときは採点しない。Word のような Kill 再起動までは入れていない。

## 18. Word VSTO の二重ロード防止

- 原因: 開発用 `New_MOSWordVSTOAddIn` と製品用 `WordMosVsto` が同時に有効になり、同じ Word にアドイン処理が二重に載っていた。P6/P9 のスクロール停止や起動の重さの主因になった。
- 対応: `VSTOInstallerHelper` で DEBUG 時は開発用、Release＋MSI 配置時は製品用だけを有効にする。開発ビルド・再インストール時に製品用の LoadBehavior を 0 にする。同時に両方を有効にしない。

## 19. PowerPoint VSTO の開発/製品分離

- 原因: PowerPoint も開発用と MSI 用で別名のアドインがあり、Word と同様に二重読み込みの余地があった。
- 対応: Word と同型の `VSTOInstallerHelper` を PowerPoint に追加し、開発時と製品時で有効にするアドインを分けた。Rebuild スクリプト側でも、開発インストール時に製品用キーを切る。
